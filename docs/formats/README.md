# Filformat i Glimt

Här ser du vilka filformat Glimt kan visa, hur de visas och vad Glimt medvetet låter bli att göra.
Glimt läser bara filen du förhandsgranskar. Den kör aldrig kod, installerar ingenting och hämtar
inget från nätet, inte ens för format som skript, profiler eller konfigurationsfiler.

## Så läser du listan

Varje format har en rad i [listan längst ned](#alla-format). Kolumnerna betyder:

- **Format**: formatets namn. Formatet kan ha egna dialekter och varianter.
- **Filändelse**: vilka filer Glimt känner igen. `.ext` är en filändelse och ett namn utan punkt,
  till exempel `Dockerfile`, är ett exakt filnamn.
- **Status**: hur väl Glimt stöder formatet (se tabellen nedan).
- **Exempelfiler**: exempel du kan titta på. Filer under `Showcase/` finns också i appens
  exempelmeny. Filer under `Cases/` används för att testa trasiga eller ovanliga filer.
- **Kommentar**: vad du ser, vad som inte stöds och vilka filändelser som krockar med andra format.

| Status | Det betyder |
|---|---|
| Stöds | Alla listade filer visas med en vy som är anpassad för formatet |
| Delvis | Bara en del av filändelserna har en anpassad vy, eller så visas formatet som ett närliggande format |
| Känns igen (Raw) | Glimt känner igen filen men visar den som ren text |
| Saknas | Glimt har inget stöd för formatet ännu. Det kan komma senare |
| Utesluten | Formatet kan inte stödjas på macOS |

## Vyer

Glimt visar en fil i en eller flera vyer. Vilka som finns beror på formatet och på vad Glimt kunde
läsa ur just den filen.

| Vy | Visar |
|---|---|
| Source | Källtexten med syntaxfärgning |
| Rendered | Det färdiga resultatet, till exempel Markdown som formaterad text eller ett Mermaid-diagram |
| Tree | Innehållet som ett träd av nycklar, värden och delar |
| Pretty | Strukturerad data omformaterad med indrag |
| Table | Rader och kolumner, till exempel CSV, loggar och arkivinnehåll |
| Diff | Ändringar i en diff eller patch, med tillagda och borttagna rader markerade |
| Raw | Filens text exakt som den är |
| Hex | Filens bytes i hexadecimal form |

I inställningen **Formats & Views** kan du välja ordning, standardvy och vilka vyer som ska visas
för varje format. Passar ingen av dina valda vyer visar Glimt Raw eller Hex i stället.

## Formatgrupper

| Formatgrupp | Exempel | Vyer |
|---|---|---|
| Källkod | Swift, Python, C/C++, JavaScript, skalskript, Dockerfile, webbserverkonfiguration och många fler | Source, Raw, Hex |
| Markdown | Markdown, R Markdown | Rendered, Source |
| Mermaid | `.mmd`, `.mermaid` och Mermaid-kodblock i Markdown | Rendered, Raw. Diagram som inte stöds visas som källtext |
| Graphviz/DOT | `.dot`, `.gv` | Source, Raw, Hex. Grafen ritas inte |
| Strukturerad data | JSON, YAML, XML, GeoJSON och property lists | Tree, Pretty, Raw. Binära property lists visas i Hex |
| JSON Lines | `.jsonl`, `.ndjson` | Tree, Raw |
| ZIP | `.zip` | Table, Hex. Visar innehållet utan att packa upp något |
| Konfiguration | TOML, INI, `.env`, Java Properties, Windows-registerfiler (`.reg`) | Source, Tree, Raw |
| CSV/TSV | `.csv`, `.tsv` | Table (standard), Raw |
| Loggar | Syslog, JSON-loggar, CEF/LEEF, accessloggar, Kubernetes och logfmt med flera | Table, Tree, Raw när innehållet kan tolkas |
| Diff/Patch | Unified diff och Git-diff | Diff, Raw |
| Övrig text | Textformat utan egen vy | Raw, ibland Hex |
| Okända binärfiler | Filer som Glimt inte känner igen | Hex |

## När en annan app visar filen

Quick Look väljer vilken app som får förhandsgranska en fil. Om en annan installerad app också
hanterar samma filtyp kan Finder välja den i stället för Glimt. Vissa filändelser delas dessutom av
flera format, till exempel `.m` (MATLAB och Objective-C) och `.ts` (TypeScript och MPEG-video).
Då avgör innehållet hur Glimt visar filen. Det står i kommentaren för respektive format.

## För utvecklare

Listan underhålls för hand. Status och sammanfattningen räknas fram från produktkatalogen
`InspectorCore/Sources/InspectorCore/Resources/formats.json` av `scripts/format-parity.py`.
Teknisk information ligger i dolda HTML-kommentarer i Kommentar-kolumnen:

- `` Katalog: `id`. `` kopplar raden till katalogen. Ett id kan delas av flera rader.
- `Manuell status: <skäl>` låser Status när filändelserna inte speglar det faktiska stödet.
- `` Evidens `id`: E2 … E5 `` är rapporterade verifieringsresultat. De ändras bara efter ny verifiering.

Lägga till ett format:

1. Lägg till en rad på rätt plats i bokstavsordning med Status `Saknas`. Exempelfiler får vara `—`.
2. Kör `python3 scripts/format-parity.py --enrich` och sedan `--check`.
3. När formatet finns i `formats.json`: lägg till `` <!-- Katalog: `id`. --> `` i kommentaren och
   länka formatets showcase och exempelfiler. Kör steg 2 igen.

`--explain` visar vad varje status bygger på. Fullt stöd kräver att formatet klarar `make test`
med egna exempelfiler. [Fixtures](../../Fixtures/README.md) beskriver exempelfilerna och
[Development](../../README.md#development) bygge och release.
