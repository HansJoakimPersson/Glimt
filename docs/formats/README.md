# Formatmasterlista

Glimts masterlista över filformat: stödda, delvis stödda och sådana som kan komma att stödjas.
`formats.json` är den faktiska produktkatalogen: endast rader med `status: supported` routas till
Glimts inspektionsflöde; `planned` betyder att en katalogpost eller framtida riktning finns men
inte innebär att formatet hanteras i appen. Masterlistans summering räknar formatrader, inte
katalog-ID:n. En filtyp som visas som Raw är igenkänd/läsbar men saknar en formatanpassad vy.
Tabellen underhålls för hand. `scripts/format-parity.py` verifierar den och skriver endast om
Status-cellerna och sammanfattningen.

| Källa | Roll |
|---|---|
| Den här filen | Äger förteckningen. Alla kolumner utom Status är manuella |
| `InspectorCore/Sources/InspectorCore/Resources/formats.json` | Äger produktens routing, parserkopplingar, Showcase-källor och tillgängliga vyer |
| [`Fixtures/`](../../Fixtures/README.md) | Testindata. `Showcase/` paketeras i appen, `Cases/` används endast av tester |
| `scripts/tests/fixtures/reference-parity.json` | Historiskt referensunderlag (SourceCodeSyntaxHighlight, QLMarkdown). Styr varken rader eller status |

## Kolumner

- **Format**: unikt namn; raderna sorteras alfabetiskt. Språkvarianter och inbäddade lexers ingår i
  huvudformatets rad. Skilda format som delar filändelse får egna rader.
- **Filändelse**: `` `.ext` `` är en filändelse, `` `Namn` `` utan punkt ett exakt filnamn. Text utan
  backticks läses inte.
- **Status**: härledd från `formats.json`, se nedan. Status räknar även en uttryckligen deklarerad
  specialiserad presentation, till exempel den native MermaidKit-renderaren, som formatstöd.
- **Fixtures**: länkar till `../../Fixtures/...`; varje länk måste finnas. Frivilligt för format som
  inte är implementerade. Ett stött katalog-id måste ha sin showcase länkad.
- **Kommentar**: produktbegränsningar, routingkonflikter och osäkerheter, plus två markörer:
  `` Katalog: `id`. `` kopplar raden till `formats.json` (ett id får delas av flera rader), och
  `Manuell status: <skäl>` fryser Status när routing på filändelse inte speglar verkligheten.
  Evidensnivåerna E2–E5 ändras endast efter ny verifiering. Befintliga evidensmarkörer
  är rapporterade resultat, inte en ny testkörning; lokala körunderlag kan vara bortstädade.

| Status | Betydelse |
|---|---|
| Stöds | Alla listade filnamn/ändelser routas till en egen inspektör eller specialiserad native renderer |
| Delvis | Bara vissa filändelser routas till en egen inspektör, eller formatet visas via ett närliggande format |
| Känns igen (Raw) | Filen känns igen men visas som ren text |
| Saknas | Ingen route |
| Utesluten | Kan inte stödjas på plattformen (kräver `Manuell status`) |

Status beskriver katalogens route och presentation, inte en ny verifiering av rendering, Finder eller release.
`python3 scripts/format-parity.py --explain` visar vilket underlag varje status bygger på.
Tillgängliga vyer kommer från katalogens representationer och kan begränsas av innehållet i den
enskilda filen. De omfattar Source, Rendered, Tree, Pretty, Table, Diff, Raw och Hex. Preview-
exempelmenyn sorteras alfabetiskt efter visningsnamn (och sökväg vid lika namn).

## Registrera ett nytt format

1. Lägg till en rad på rätt alfabetisk plats med Status `Saknas`. Fixtures får vara `—`.
2. Kör `python3 scripts/format-parity.py --enrich` och sedan `--check`.
3. När formatet implementeras i `formats.json`: lägg till `` Katalog: `id`. `` och länka dess
   showcase och fixtures. Kör steg 2 igen.

Kvalitetskravet för fullt stöd är att formatet klarar `make test` med egna fixtures; bygg och
release beskrivs i [RELEASING.md](../../RELEASING.md).

## Format som appen presenterar

`Formats & Views` låter användaren ändra ordning, standardvy och aktiva vyer för varje stödd
formatpost. Den faktiska listan för en fil är skärningen mellan katalogens vyer, användarens val
och innehållet som inspektören kunde tolka. Om ingen vald vy passar visas Raw eller Hex som fallback.

| Formatgrupp | Exempel | Vyer i appen |
|---|---|---|
| Syntaxmarkerad källkod | Språk och format med katalogerat source-språk, till exempel Swift, Python, Elm, C/C++, JavaScript, Shell, webbserverkonfiguration, Dockerfile, DTD och XQuery | Source, Raw, Hex |
| Markdown | Markdown, R Markdown | Rendered, Source |
| Mermaid | `.mmd`, `.mermaid` och Mermaid-kodblock i Markdown | Native Rendered, Raw; innehåll MermaidKit inte stöder visas som källa |
| Graphviz/DOT | `.dot`, `.gv` | Katalog: `graphviz`; [graph.dot](../../Fixtures/Showcase/source/graph.dot). Bounded Source/Raw/Hex med lexikal markering; HTML-liknande etiketter förblir opaka. Ingen grafmodell, layout eller ritning. Grafrendering kräver fortsatt ägarens licensbeslut och en native ritadapter enligt föreslagen ADR-032. |
| Strukturerad data | JSON, YAML, XML, GeoJSON och property lists | Tree, Pretty när parsern kan skapa den, Raw (hex för binära property lists); GeoJSON visar en begränsad geometri- och koordinatsammanfattning |
| JSON Lines | `.jsonl`, `.ndjson` | Tree, Raw |
| ZIP | `.zip` | Table, Hex; lists metadata only, never opens or extracts entries |
| Konfiguration | TOML-delmängd, INI/`.env`, Java Properties, Windows Registry `.reg` | Source, Tree, Raw |
| CSV/TSV | `.csv`, `.tsv` | Table (standard), Raw (originaltext) |
| Loggar | Syslog, JSON, CEF/LEEF, accessloggar, Kubernetes CRI och logfmt med flera kända rader | Table, Tree, Raw när innehållet kan tolkas |
| Diff/Patch | Unified/Git diff och patchar | Diff, Raw |
| Övrig igenkänd text | Textformat utan egen inspektör eller syntaxmarkerad Source-vy | Raw; vissa format erbjuder Hex |
| Okända binärfiler | Innehåll utan identifierad formatroute | Hex |

Showcase-exemplen i dropdownen för förhandsgranskning sorteras alfabetiskt efter namn. Den
fullständiga masterlistan nedan innehåller också format som inte stöds ännu och anger dem som
`Saknas`; deras fixtures är referens-/testmaterial, inte ett löfte om appstöd.
