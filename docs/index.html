Quick Look inspector for macOS

Glimt

Open a file in Glimt to inspect source code, Markdown or structured data. When Finder selects Glimt, press Space to see the same inspection in Quick Look.

Build from source View on GitHub

Requires macOS 15 or later · Open source · No release yet

One inspector instead of many plugins

Readable, honest previews for the files you work with.

Glimt uses the filename, file type and up to 64 KiB of content to choose how to inspect a regular file. It then reads within the selected inspector’s limits and shows a diagnostic when a view is unavailable.

Structured data

Tree, Pretty or Raw.

JSON, YAML and XML offer a collapsible tree, formatted text when available, and original text in Raw. YAML files with multiple documents show each document separately in Tree. Invalid input keeps Raw available with a diagnostic. Property lists open in a typed Tree by default. Raw shows original text for text property lists and a bounded hexadecimal view of the original bytes for binary property lists. JSON Lines (.jsonl and .ndjson) opens in Tree with one JSON value per record and keeps the source available in Raw.

The original file is never changed. Every view is presentation only.

Settings

Tune it once, see it live.

Adjust appearance, fonts, wrapping and limits in Settings, then configure each format’s views and default in Formats & Views. The preview beside the settings updates as you change them.

VCS Support in Advanced settings is off by default. When enabled, Glimt can mark changed lines for files in local Git or Subversion working copies after the preview opens. Repository access is read-only.

Inquiry shows how Glimt reads any file you drop on it.

Supported formats

From plain text to property lists.

These families use Glimt’s bounded engine. Individual syntax, views and format coverage have documented limits; Finder may select another provider. See the format coverage and limitations.

Structured data

JSON, YAML and XML (.xml) offer Tree, Pretty when available, and Raw. For XML documents with repeated records directly under the root, Table can show one row per record, with attributes and immediate child elements as columns. Tree still shows the XML hierarchy. XML Schema (.xsd) and XSLT (.xsl, .xslt) use the XML views. Glimt rejects external DTDs, never loads external resources, and performs no schema validation or transformations.

Property lists (.plist, .loctable, .wflow) open in Tree and offer Pretty when formatted text is available. Raw shows the original text for XML and OpenStep property lists and a bounded hexadecimal view of the original bytes for binary property lists.

Glimt accepts a subset of JSON5 (.json5) with comments, trailing commas and single-quoted strings. Supported Zig Object Notation files (.zon) also use the JSON tree. Raw preserves the original source. YAML files (.yaml, .yml, .flow) show each document separately in Tree when the file contains multiple documents.

JSON Lines (.jsonl, .ndjson) accepts one JSON value per line, including objects, arrays and scalars. Tree keeps records in file order, skips blank lines and shows a line-numbered diagnostic for malformed records. Raw keeps the original text.

Local X.509 previews show the subject, issuer when available, serial number, validity dates and SHA-256 fingerprint. Glimt accepts up to 16 certificates per PEM bundle (.pem, .crt) and one certificate per DER file (.der, .cer). Private-key PEM blocks are rejected. Glimt does not import certificates or evaluate trust. Raw and Hex remain available for unreadable certificates.

Supported certificate-only PKCS#7 bundles (.p7b, .p7c) show certificate subjects and SHA-256 fingerprints in Tree. Glimt accepts up to 16 certificates in a DER or PEM bundle. Signature and trust status remain unchecked. Unreadable bundles retain Raw or Hex according to the file’s contents.

Supported DER PKCS#12 version 3 files (.p12, .pfx) show the version, count and types of up to 16 envelopes, and whether MAC data is present. Glimt leaves the payload opaque and performs no decryption or MAC verification. Hex is available when inspection fails.

GeoJSON (.geojson) opens in Tree. For supported features and geometries, Tree shows a bounded summary of feature names, geometry types, coordinate counts and longitude and latitude bounds where available. Pretty formats parsed JSON, and Raw shows the original source. If valid JSON cannot be summarized as GeoJSON, Glimt keeps the standard JSON views. Previewing GeoJSON requires no maps or network requests.

KML (.kml) and GPX (.gpx) offer a Tree summary of placemarks and geometries or waypoints, routes and tracks, with coordinate bounds where available. Pretty shows formatted XML when available, and Raw shows the original XML. Glimt displays the summary without loading maps or external resources.

Readable mount tables named exactly fstab offer a bounded Tree of filesystem specifications, mount points, filesystem types and options. Raw shows the original text within the preview’s read limit. Glimt leaves mount settings unapplied.

Dotenv files such as .env, .env.local and service.env open in Tree with parsed entries. Raw shows the original text, and Glimt leaves variable references and commands unevaluated. Windows Registry exports (.reg) offer a bounded Tree of keys and values, Raw for the original text, and Hex for the underlying bytes. Glimt never applies the export.

Glimt recognises SQLite databases by the .sqlite and .sqlite3 extensions or the SQLite 3 file signature. Tree shows table and view names and definitions within inspection limits. Glimt opens the database read-only and never queries stored rows. Thumbnails show schema counts only. Raw and Hex remain available when schema inspection fails.

Glimt uses the .zip suffix to identify supported classic, single-disk ZIP archives. Table lists entries in archive order with names, file or directory types, and declared compressed and uncompressed sizes. Empty ZIP archives show an explicit empty state. Glimt reads archive metadata without extracting or verifying member contents. Malformed archives, archives that exceed inspection limits, and unsupported variants such as ZIP64 or encrypted archives fall back to Raw or Hex without showing a partial inventory.

USTAR archives (.tar, .tar.gz and .tgz) open in Table with a bounded inventory of entry names, types, sizes and link targets. Thumbnails show entry counts only. Glimt never extracts files or renders their contents. Unsupported variants such as PAX and GNU long-name archives show a diagnostic with Raw and Hex available.

Supported provisioning profiles (.mobileprovision) contain a property list wrapped in CMS SignedData. The preview shows selected declarations such as the profile name, UUID, team identifiers, dates, platforms and entitlements. It omits embedded developer certificates. Glimt leaves the signature and profile usability unchecked and never installs the profile. Encrypted, malformed, incomplete or oversized profiles fall back to Hex without showing partial metadata.

Supported compact JWS tokens (.jwt) show the decoded header and claims, the declared algorithm, and whether a signature is present. Glimt labels the claims as unverified and performs no signature verification or claim validation. The header and claims must both be JSON objects. Encrypted five-segment JWE tokens, duplicate JSON keys, invalid base64url and other malformed, incomplete or oversized inputs retain Raw and Hex without showing partial claims.

JSON Web Key files (.jwk) show one RSA, EC, OKP or octet key in Tree. JSON Web Key Sets (.jwks) show 1–256 keys of those types. Tree redacts standard private and symmetric key values, and thumbnails omit those values. Glimt previews key metadata locally without importing or verifying keys. Duplicate JSON members and malformed key objects fall back to Raw and Hex. Those views can expose private key material from the original file.

Glimt uses the contents of .pub files to distinguish OpenSSH public keys from PEM public keys. OpenSSH previews show the algorithm, key size, comment when present and SHA-256 fingerprint. Supported PEM public keys show metadata such as the algorithm and key size. Glimt reads public key metadata locally without importing keys or assessing trust.

Glimt previews CycloneDX JSON 1.4–1.7 (.cdx.json or bom.json) and SPDX JSON 2.2–2.3 (.spdx.json) in Tree. Glimt checks format and version markers within its JSON inspection limits. Thumbnails show counts without exposing component values. Glimt leaves external references unopened and performs no schema or semantic validation. Duplicate JSON members, malformed or incomplete files, unsupported versions and files that exceed inspection limits retain Raw and Hex without showing partial SBOM data.

Tree also supports CycloneDX XML 1.4–1.7 (.cdx.xml or bom.xml) and SPDX 2.2–2.3 in Tag-Value (.spdx) or single-document YAML (.spdx.yaml, .spdx.yml). Glimt checks format markers and structure within inspection limits. Tag-Value keeps repeated tags and continuation lines in order, and XML rejects DTDs and external entities. Thumbnails show summary counts and omit component values. Glimt leaves external references unopened and performs no full schema or semantic validation. Malformed, incomplete, unsupported or oversized files retain Raw and Hex without showing partial SBOM data.

Glimt uses the .cdx.pb suffix for CycloneDX protobuf versions 1.5–1.7. Tree shows selected document and component fields, including component names and versions when present. Thumbnails show the schema version and component count. Glimt reads a bounded set of fields without validating the full schema or following external references. Malformed files and unsupported versions fall back to Raw or Hex.

Email files (.eml) show headers, plain-text bodies and attachment metadata in Tree. The preview omits HTML and encoded payloads. Attachments stay unopened.

iCalendar files (.ics) show components and their properties in Tree without expanding recurrences or resolving time zones. vCard files (.vcf) show one or more contact cards, with inline binary data omitted. Glimt previews both formats without importing events or contacts. Across all three formats, links stay inert and Raw remains available when structured inspection fails.

Apple privacy manifests (PrivacyInfo.xcprivacy and other .xcprivacy files) show declared tracking, collected data and accessed API reasons in Tree and Pretty. Glimt checks the structure of recognized property-list keys and preserves unknown keys. Thumbnails show counts only. The preview performs no App Store compliance review. Malformed manifests retain Raw or Hex.

Xcode string catalogs (.xcstrings) and supported version 1 test plans (.xctestplan) open in Tree by default. Pretty shows formatted JSON when available, Raw shows the original text, and Hex shows the underlying bytes. String catalog thumbnails show only string and locale counts. Test plan thumbnails show target and configuration counts only. Glimt previews test plans without running tests or opening referenced project files. Malformed or unsupported catalogs and test plans retain Raw or Hex.

Xcode schemes (.xcscheme) offer Tree, Pretty when available, and Raw for the original XML. Glimt rejects DTDs and external entities, and never runs scheme actions or builds targets. Malformed or unsupported schemes retain Raw or Hex.

Xcode project files (.pbxproj) open as OpenStep property lists, and workspace metadata (.xcworkspacedata) opens as XML. Both offer Tree, Pretty when available, and Raw. Glimt never evaluates project objects or opens referenced projects. Build configuration files (.xcconfig) offer syntax highlighting in Source without expanding includes or build settings. Raw remains available for retained content when inspection fails or reaches a limit.

Files named exactly CodeResources use the property-list views when their resource-map structure is recognized. Thumbnails show counts only. Glimt displays the resource metadata without verifying code signatures or bundle integrity. Malformed or unsupported files retain Raw or Hex.

Aa

Text and tables

Plain text with encoding and line-ending detection. CSV and TSV open in Table by default, using the first record as column headers. Table supports quoted fields that span lines and rows of different lengths. Malformed or incomplete input and files that exceed inspection limits can show a diagnostic with Raw available for the retained text.

Log files (.log, .syslog, .cef and .leef) offer Table and Tree for recognised records, including Syslog, JSON logs, logfmt and common web server access logs. Table shows event fields such as timestamp, severity and message. Tree preserves nested fields. Raw shows the retained original text, including unrecognised lines, and remains available when the structured preview reaches its limits.

Unified and Git diff files (.diff and .patch) show changed files and hunks in Diff, with added, removed and context lines. Glimt shows diagnostics for malformed hunks or inspection limits. Raw shows the retained patch text. Glimt previews patches without applying them.

01

Local and offline

Glimt never uses the network. Remote images and links stay inert text.

02

Never executes content

Rendering is native. Glimt never runs scripts or external tools and never loads file content in a browser engine.

03

Bounded by design

Quick Look previews and thumbnails use at most 64 KiB of regular-file content to select an inspector. A TextBundle shares that budget across its manifest and Markdown sample. The selected inspector has its own limits. Oversized or unsupported input can fall back to a limited readable view. Inspection has a 2-second deadline for previews and a 1-second deadline for thumbnails. If it times out, Glimt can fall back to the bytes already read.

Build from source

Build and try Glimt.

Beta builds are published on GitHub Releases; they are not yet notarized. You can also build and run the host app with Xcode on macOS 15 or later. Finder and Quick Look provider selection remains unverified for the current candidate and can be affected by other installed apps.

Start with the README for building, testing and installing, and RELEASING.md for packaging and releases.

  1. 1
    Clone the repository

    Get the source from GitHub.

  2. 2
    Build and test

    Open Glimt.xcodeproj and build the Glimt scheme. Routine builds and tests need no local config or developer team.

  3. 3
    Run it

    Run the Glimt scheme with Xcode's Sign to Run Locally. make test runs the full unsigned test gate and make package builds the release archive.
